# 已知問題與修正紀錄

## 生成圖片期間切換頁面後，聊天室顯示 `Load failed`

- 發現日期：2026-07-24
- 環境：AWS EC2 production（https://safu-studio.com）
- 狀態：已在本機修正並通過測試，納入下一次 EC2 更新

### 重現方式

1. 在聊天室送出圖片生成請求。
2. 圖片仍在生成時切換到「我的圖片」。
3. 生成完成後回到聊天室。
4. 聊天室顯示 `Load failed`，但「我的圖片」已有生成完成的圖片。

### 原因

圖片生成及儲存實際上成功，但前端離開頁面後，等待中的請求或輪詢可能中斷。回到聊天室時，舊版前端沿用本機暫存狀態，沒有重新向後端核對 generation job 的最終結果，因此錯誤顯示為失敗。

### 本機修正

- 開啟聊天室時，重新從後端取得最新聊天室內容。
- 前端遇到網路錯誤、代理層 `5xx` 或 `504` 時，沿用原 `Idempotency-Key` 查回同一個 generation job；若仍在執行則輪詢，不建立第二個請求。
- 圖片 API 單次 timeout 為 300 秒且 SDK 不自動重試；後端確認 `failed` 後，前端才顯示「修改失敗，請重新送出要求。」
- 後端讀取聊天室時，也會將已完成的 generation job 同步回聊天室訊息。
- 聊天 exchange 保存明確的 `failed` 狀態；失敗訊息不顯示圖片 placeholder，也不會誤顯示成「儲存期限已過」。
- 新增測試，涵蓋「使用者離開頁面期間工作已完成」的情況。

### 驗證結果

- 後端測試：36 passed。
- 前端 production build：成功。
- 待部署至 EC2 後，以實際切換頁面流程再驗收一次。

## 手機初始畫面需要手動縮小

- 發現日期：2026-07-24
- 狀態：已在本機修正並通過 production build，納入下一次 EC2 更新

### 原因與修正

部分內容使用固定寬度，搭配頁面最小寬度後可能超出較窄手機的 viewport。已移除頁面最小寬度、將文化元素卡片改為彈性欄寬、加入窄螢幕間距與 safe-area 支援，並避免 iPhone 聚焦小字輸入框時自動縮放。

### 待驗收

- 以實際手機直接開啟登入頁與聊天室，不應需要手動縮小。
- 測試文化元素、我的圖片、圖片詳細頁與聊天室均無水平捲動。
- 測試輸入框聚焦與返回頁面後，頁面縮放比例維持正常。

## 打開聊天室會改變最近對話排序與到期時間

- 發現日期：2026-07-24
- 狀態：已修正並通過自動測試，納入下一次 EC2 更新

### 原因與修正

舊版讀取單一聊天室時會更新 `updated_at` 與 `expires_at`，前端載入完成後也可能立即將相同內容回存。因此只是查看舊聊天室，也會將它移到最近對話第一個並延長期限。

現在 GET 聊天室原則上是純讀取，前端也會跳過載入後的第一次自動儲存。最近對話依最後一次訊息／內容更新排序；只有真正同步內容才重新計算 14 天保存期限。若 generation job 已完成但 pending 訊息缺少結果，第一次對帳會視為真正內容更新，同步更新 `updated_at`、聊天室期限及訊息期限；對帳完成後再次讀取不會重複刷新。列表會在對帳後重新排序並排除已到期聊天室。

## 商品圖尚未到期但顯示破圖

已修正。舊版的商品圖或輔助圖可能使用自己的 `ImageAsset.expires_at`，列表卻顯示外層 `ImageRecord.expires_at`；當兩者不同時，卡片會顯示尚未到期，但受保護圖片路由已拒絕讀取 asset。

現在一個 `ImageRecord` 代表完整圖片版本，旗下 active assets 共用版本期限。成功產生新商品圖或輔助圖時刷新整個版本；收藏、saved 狀態與單純查看不延長期限。清理以版本為單位，且共用 `storage_key` 會保留到最後一個引用版本移除。Migration `d6f1a8c42e7b` 負責同步既有資料。

## 收藏頁與預設資料夾名稱相同

- 發現日期：2026-07-24
- 狀態：已修正並通過自動測試，納入下一次 EC2 更新

### 原因與修正

收藏功能的頁面名稱與舊版預設系統資料夾都叫「我的收藏」，進入資料夾後不容易辨識目前層級。現在保留功能頁與選單的「我的收藏」，並將預設系統資料夾顯示為「我的最愛」。

API 也相容正式環境既有的舊資料；即使資料庫仍保存舊名稱，畫面會顯示「我的最愛」，且不會修改使用者自行建立的資料夾。

## 更換商品圖後「我的圖片」重複顯示相同圖騰或輔助圖

- 發現日期：2026-07-28
- 狀態：已修正並通過自動測試

### 原因與修正

商品 variant 會建立新的 `ImageRecord`，並讓新 record 的 motif／chart asset 繼續引用原本的實體檔案。實體檔案沒有重複複製，但舊版 `/api/v1/images/assets` 依 `record_id + asset_type` 逐筆回傳，因此「我的圖片」仍會看到多張內容相同的資產。

現在資產列表以 `asset_type + URL` 去重，並優先保留最早建立的原始 record。每次真正生成、URL 不同的商品預覽仍各自顯示；資料庫中的衍生 record、來源關係與共用檔案引用完整保留。

## API 或第三方服務錯誤可能直接顯示英文

- 發現日期：2026-07-28
- 狀態：已修正並通過自動測試

### 原因與修正

舊版前端部分路徑直接顯示後端的 `detail`、`detail.message`、generation job `error_message` 或 JavaScript `error.message`。當錯誤來自 FastAPI、OpenAI SDK、網路層或舊聊天室紀錄時，使用者可能看到英文或技術訊息。

現在後端錯誤統一回傳穩定 `code` 與安全中文 `message`，FastAPI `422` 與未知例外也經全域處理；原始技術錯誤只留在安全 log。前端只顯示已知代碼的中文對照，未知錯誤與舊聊天室純英文失敗訊息一律改用中文通用提示，不直接顯示原始內容。
